# Mission P43 — Activer la lecture des plantages (Android vitals)

- **Voie** : b (mission navigateur). Voie a écartée : la CI pourrait l'activer si `gh-deployer` recevait
  `roles/serviceusage.serviceUsageAdmin`, droit trop large pour un geste unique.
- **Durée** : 2 min. **Quand** : maintenant.
- **Pourquoi** : le bilan de « Play — AAB » dit « API Google Play Developer Reporting pas activée » ; sans elle, la
  routine ne voit ni plantages ni ANR (retour (2) du 04/11, VITALS-1).

## Étapes

1. Ouvrir https://console.cloud.google.com/apis/library/playdeveloperreporting.googleapis.com?project=healthtrack-824b26
2. Vérifier en haut de page que le projet sélectionné est **healthtrack-824b26**. Sinon, s'arrêter.
3. Si le bouton **Activer** est affiché : cliquer dessus et attendre la page « Détails de l'API ».
   Si la page dit déjà « API activée » ou propose « Gérer » : ne rien toucher.
4. Ouvrir https://play.google.com/console → app **Halcya** (`fr.jpesquet.sante`) → menu de gauche
   **Utilisateurs et autorisations** (au niveau du compte, pas de l'app) → ligne
   `gh-deployer@healthtrack-824b26.iam.gserviceaccount.com` → onglet **Autorisations de l'application** → Halcya.
5. Si **Afficher les informations de l'application (lecture seule)** n'est pas cochée : la cocher, puis
   **Appliquer** / **Enregistrer les modifications**. Ne décocher rien, ne cocher aucune autre case
   (surtout pas « Publier en production » ni « Administrateur »).

## Vérification finale

- Page de l'API : mention « API activée ».
- Autorisations de gh-deployer pour Halcya : « Afficher les informations de l'application » cochée, les cases
  déjà cochées (versions des canaux de test, testeurs, présence sur le Store, produits) inchangées.

**Capture attendue** : la page « API activée ». **Phrase de retour** : « P43 fait ».
