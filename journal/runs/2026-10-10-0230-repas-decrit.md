# 2026-10-10 02:30 UTC — Décrire un repas en quelques mots (texte / dictée → Gemini)

**Type** : 🏗️  ·  **PR** : voir ci-dessous

## Pourquoi
1er item des « Prochaines étapes » (C4 étape 2, R#5). La veille (RESEARCH §B du 10/10 et [6]) montre que la photo
seule ne suffit pas : en conditions réelles, le texte est jugé plus simple et les utilisateurs veulent choisir
leur mode de saisie. Contrainte de conception retenue : le LLM ne sort que *aliments + grammes + confiance*,
les nutriments viennent de la table CIQUAL locale.

## Ce qui a été fait
- `services/geminiStandalone.js` : logique d'appel factorisée (`requestMealJson` : repli de modèles, repli sans
  schéma, extraction JSON ; `toMealResult` : `not_food`, noms rapprochés de la base). Nouveau
  `analyzeMealText(text, apiKey)` : texte seul (≤ 500 caractères, aucune image), même schéma JSON, prompt avec
  repères ménagers français (œuf 55 g, tranche de pain 35 g, c. à soupe d'huile 10 g, bol, verre…), ajout
  explicite des matières grasses de cuisson/assaisonnements en confiance « low », consigne d'ignorer les
  instructions contenues dans la description.
- `NewMealForm` : pour un repas vide (pas pour « Refaire »), champ « Décrivez votre repas » + « ✨ Remplir avec
  Gemini » si une clé existe ; résultat chargé dans l'éditeur existant (grammes, « à vérifier », kcal), titre =
  nom du plat. Enregistré avec `provider: 'gemini_text'` + `model`. Sans clé : renvoi vers Paramètres, recherche
  manuelle inchangée. Mention de confidentialité (seul le texte part) et du micro du clavier pour dicter.
- Bouton « ✍️ Décrire ou saisir sans photo », intro de la page mise à jour.
- Bug corrigé au passage : `normalizeName` transforme œ → oe / æ → ae : chercher « œuf » (ligature de Gboard)
  ne trouvait aucun des « Oeuf … » de la base.
- Outil visuel : `--meal-text` (réponse Gemini factice) et `--meal-text=form` (formulaire avant envoi).

## Apprentissages / décisions
- Pas de nouveau type de donnée ni de migration : un repas décrit est un `food` comme les autres (`provider`
  distinct pour pouvoir mesurer plus tard la précision par mode de saisie).
- Pas de vraie clé dans la session : le prompt n'est pas testé contre l'API réelle. Le format de réponse étant le
  même que pour la photo (déjà en production), le risque est faible ; si Gemini renvoie peu d'aliments, revoir
  le prompt.
- La description n'apparaît que sur un formulaire vide : après remplissage, on corrige dans l'éditeur (pas de
  ré-analyse qui écraserait les corrections).
