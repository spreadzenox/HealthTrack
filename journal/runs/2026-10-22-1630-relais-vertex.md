## Ce qui a été fait
- `relay/` (Node 22, **aucune dépendance**) :
  - `server.js` : `POST /v1/meal/analyze` (`X-Install-Id` aléatoire 16–64 car. ; `kind: 'photo'` JPEG en base64 ou
    `kind: 'text'` ≤ 500 car.) → `{ parsed, model, quota: { remaining, resetAt } }` ; `GET /healthz` ; 429 avec
    message français et `scope` (install / global / minute) ; 502 générique si le modèle échoue ; CORS limité aux
    origines de la WebView ; corps ≤ 6 Mo, photo ≤ 4 Mo. Journaux JSON sans contenu ni identifiant en clair.
  - `prompts.js` : mêmes consignes et même schéma que l'appel direct de l'app (le décodage côté app reste le même),
    construites par le relais ; la liste des 3 553 ingrédients est en tête (consigne système identique d'un appel à
    l'autre → cache implicite de Vertex AI, coût réduit).
  - `vertex.js` : Gemini sur Vertex AI (`{région}-aiplatform.googleapis.com`), jeton OAuth du serveur de métadonnées
    (compte `relay-runtime`), modèles × régions essayés dans l'ordre (404/403 → suivant, le couple qui marche est
    retenu), repli sans schéma, délai 45 s ; erreurs marquées « facturées » ou non.
  - `quota.js` : plafonds par installation / jour (20), global / jour (200), global / minute (10) ; un appel qui n'a
    rien coûté est rendu.
  - `jpeg.js` : retrait APP1–APP15 et commentaires (+ octets de remplissage), refus de ce qui n'est pas un JPEG complet.
  - `Dockerfile` (node:22-alpine, utilisateur `node`), `README.md`.
- `.github/workflows/relay-deploy.yml` « Relais — déploiement » : tests → WIF (gh-deployer) → image dans Artifact
  Registry → `gcloud run deploy halcya-relay` (relay-runtime, public, 0–1 instance, plafonds en variables) →
  `/healthz` + une vraie analyse de texte (rouge si elle échoue, avec la piste : modèle absent de la région ou rôle
