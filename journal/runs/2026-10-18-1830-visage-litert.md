## Ce qui a été fait
- **Choix du moteur** : POM vérifiés sur le Maven de Google. LiteRT **2.2.0 / 2.3.0** dépendent de
  `com.google.android.play:ai-delivery` (services Play), Guava, coroutines, lifecycle → contraire à I94 (pas de
  dépendance d'envoi). **LiteRT 1.4.2** : aucune dépendance transitive, même API `org.tensorflow.lite.Interpreter`,
  XNNPACK intégré → retenue.
- **`face-models.gradle`** (tâche `faceModels`) : télécharge le `.task` depuis l'URL **versionnée** `float16/1` (même
  SHA-256 que `latest`, vérifié), gardé dans le cache Gradle de la machine, 3 essais espacés ; extrait les 3 `.tflite`,
  vérifie leurs SHA-256 complets, les range dans `build/generated/faceModels/face/` (jamais committés). Testé hors SDK
  Android avec Gradle 8.14 : 1er passage (téléchargement), 2e `UP-TO-DATE`, fichier corrompu → réextrait du cache
  hors ligne.
- **`build.gradle`** : assets générés ajoutés, `noCompress 'tflite'` (projection mémoire), `abiFilters 'arm64-v8a',
  'x86_64'` (I95), `preBuild` + `merge*Assets` dépendent de `faceModels`, assets de `androidTest` = vecteurs de
  `src/test/resources`.
- **`LiteRtModel`** (implémente `FacePipeline.Model`) : entrée float32, tampons directs alloués une fois, 1 thread,
  sorties **choisies par nom** (`regressors`/`classificators`, `Identity`/`Identity_1` ; noms lus avec LiteRT Python),
  repli sur l'ordre des index ; **`FaceModels`** : ouvre les 3 modèles depuis les assets (projetés, sans copie),
  `available()` pour un APK construit sans modèles, `pipeline()`.
- **`FaceModelsTest`** (instrumenté) : formes des entrées ; sorties brutes du détecteur, du maillage et des
  blendshapes contre les vecteurs de 14:30 ; pipeline complet (aucun rejet, blendshapes moyen < 0,02, sourire ± 0,05) ;
  temps par image dans logcat. `run-emulator-tests.sh` le lance et **fait échouer le job** si le résultat n'est pas
  « OK » (vérifié en fin de script, après les captures).
- Spec `protocoles/visage.md` §7.2 (choix du moteur, noms des sorties, tâche, ABI, tolérances).
