# 2026-10-10 04:30 UTC — Restaurer une sauvegarde sans risque

**Type** : 🐛  ·  **PR** : voir le tableau du résumé

## Pourquoi
1er item des « Prochaines étapes » : chasse aux bugs sur les interactions, dont l'import d'une ancienne sauvegarde
(dernier run 🐛 : 09/10 20:30). Lecture de `Data.jsx` / `importFromJson` : **choisir un fichier dans Données →
Importer effaçait immédiatement toute la base**, sans confirmation ni vérification. Conséquences possibles :
- choisir par erreur un autre JSON (export d'une autre appli, tableau quelconque) → `store.clear()` puis insertion
  d'entrées sans type ni source : **toutes les données perdues** ;
- restaurer une sauvegarde plus ancienne → tout ce qui a été saisi depuis disparaît, sans avertissement ;
- entrée sans date → enregistrée « maintenant » (fausse les analyses du jour).

## Ce qui a été fait
- `storage/localHealthStorage.js` : `parseBackup(json)` (pur, sans écriture) — vérifie le fichier, accepte le format
  actuel et l'ancien tableau nu, ignore et compte les entrées illisibles (sans type, sans source, date absente ou
  invalide), décode un `payload` stocké en chaîne JSON ; renvoie date d'export, période, nombre par type. Refuse un
  fichier sans aucune entrée reconnue.
- `importFromJson` passe par `parseBackup` : jamais de `clear()` si le fichier est invalide ou vide ; nouveau mode
  `merge` qui n'ajoute que les entrées absentes (clé source + date + type, comme `upsertEntries`) → ré-importer le
  même fichier ne crée aucun doublon. Retour `{ imported, skipped, invalid }`. Pas de changement de schéma.
- `pages/Data.jsx` : import en deux temps — aperçu (« Sauvegarde du 10 oct. 2026 · 1 078 entrées du … au … ·
  132 repas · 75 notes de bien-être · … »), puis « Ajouter à mes données » (recommandé), « Remplacer mes données »
  (2ᵉ confirmation qui annonce combien d'entrées actuelles seront supprimées, bouton rouge) ou « Annuler ».
  Messages de résultat : « N entrées ajoutées (M déjà présentes, non dupliquées) », « Aucune nouvelle entrée ».
- Outil visuel : `--import` (aperçu d'une sauvegarde de démo + 1 entrée illisible) et `--import=replace`.

## Vérifications
- Tests : 588 ✅ (571 avant ; +10 stockage, +7 page Données) · Lint : 7 erreurs, 1 warning (inchangé) · Build ✅
- Visuel : toutes les pages (démo) sans erreur JS ; `/data --import --viewport` (aperçu lisible, avertissement orange
  pour l'entrée illisible), `--import=replace` (confirmation rouge, nombre d'entrées actuelles), et
  `--import --click="Ajouter à mes données"` sur un vrai IndexedDB : « Aucune nouvelle entrée (1 078 déjà présentes,
  non dupliquées) · 1 entrée illisible ignorée » → dédoublonnage vérifié de bout en bout.

## Apprentissages / décisions
- « Ajouter » est l'action par défaut (bouton principal) : elle ne peut rien perdre. « Remplacer » reste possible
  (repartir d'une base propre) mais demande deux taps explicites.
- Le dédoublonnage ne porte que sur les entrées déjà présentes, pas à l'intérieur du fichier (deux saisies légitimes
  à la même seconde restent deux entrées).
- Les nombres (« 1 078 ») s'affichent avec l'espace fine de `toLocaleString('fr-FR')`, comme ailleurs.
