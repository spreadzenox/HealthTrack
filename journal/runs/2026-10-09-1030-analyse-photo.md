# 2026-10-09 10:30 UTC — Analyse photo fiabilisée (grammes modifiables, schéma JSON)

**Type** : 🏗️  ·  **PR** : #71 (fusionnée → release v70)

## Pourquoi
Priorité n°1 du backlog (R#4). L'estimation des portions sur photo est le point faible connu des
LLM (erreurs de plusieurs dizaines de % sur les grammes) ; or l'app enregistrait la réponse telle
quelle, sans possibilité de correction, et **jetait en silence** tout ingrédient dont le nom ne
correspondait pas exactement à la base (casse, accent, virgule) — repas incomplets dans Nutrition.

## Ce qui a été fait
- `services/mealEditing.js` (+ 16 tests) : rapprochement des noms avec la base Ciqual (casse,
  accents, virgules/apostrophes ignorés ; nom exact prioritaire), recherche d'ingrédients
  (tous les mots, préfixe puis noms courts d'abord), grammes bornés 0–5 000 g (virgule acceptée),
  kcal par ingrédient et par repas.
- `services/geminiStandalone.js` : `responseSchema` (not_food, reason, dish, ingredients[ingredient,
  quantity_g, confidence high/medium/low]) ; si un modèle refuse le schéma (400 mentionnant
  « schema »), même requête sans schéma (pas de régression possible) ; prompt : repères de
  portion (assiette ≈ 26 cm…), éléments peu visibles (huile, sauce) en confiance « low » ;
  ingrédients inconnus gardés avec `unknown: true` au lieu d'être supprimés (+ 3 tests).
- `components/MealEditor.jsx` (+ 7 tests) : liste éditable — champ grammes + boutons −/+ 10 g
  (cibles 44 px), kcal par ligne, total, ✕ supprimer, badge « à vérifier », aliment absent de la
  base signalé avec bouton « Remplacer » (garde les grammes), recherche « Ajouter un ingrédient »
  (100 g par défaut). Verrouillée une fois le repas enregistré.
- `pages/Food.jsx` : titre = nom du plat, avertissement « vérifiez les quantités », enregistre les
  items corrigés (+ `dish`, sans le drapeau `unknown`) ; si rien n'est reconnu, on peut ajouter les
  ingrédients à la main ; derniers repas avec nom du plat et ≈ kcal (+ 2 tests).
- Outil visuel : option `npm run visual -- --routes=/food --food-analysis` (clé factice, réponse
  Gemini simulée, photo 1×1 importée puis « Analyser »).
- Lint : catch vide de `Food.jsx` commenté (9 → 8 erreurs).

Schéma de données : seul un champ optionnel `payload.dish` (et `confidence` par item) s'ajoute aux
repas ; aucun changement IndexedDB, export/import inchangés, anciens repas lus normalement.

  cas d'un refus. **À confirmer avec le propriétaire.**
